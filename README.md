# TodoTimer

在 Obsidian 中持续记录任务、后续行动、卡点和等待事项，自动添加时间。无需分类、标签或独立任务面板。

当前版本为 0.1.3，任务创建标记改为 `📝`，完成标记保持 `✅`。检查范围与结果见[验证记录](docs/verification.md)。

```md
- [ ] 上架 XXXX 系统到测试 📝 20260101 17:00
  - 卡点：需要先整理网络规则 20260102 08:00
  - [x] 整理网络规则 📝 20260102 08:05 ✅ 20260102 10:30
  - 等待：网络管理员开通权限 20260102 10:40
```

## 安装

首版面向 Windows 桌面版 Obsidian 1.12.7 及以上版本；实际验收版本为 1.14.4，最低版本与移动端尚未单独验收。

1. 解压 `dist/todotimer-0.1.3.zip`，得到 `todotimer` 文件夹。
2. 将整个文件夹放到笔记库的 `.obsidian/plugins/` 下。最终应有 `.obsidian/plugins/todotimer/main.js`、`manifest.json`、`styles.css`。
3. 在 Obsidian 的“设置 → 第三方插件”中启用 TodoTimer；必要时重新加载 Obsidian。

从旧版本更新时，覆盖插件目录中的上述三个文件并重新启动 Obsidian。

插件启用后对所有 Markdown 笔记生效，不需要逐篇开启。使用 Obsidian 自带的插件开关即可停止自动记录。

## 日常使用

- 输入非空 `- [ ]` 任务，按 Enter、离开当前行或切换笔记时，追加 `📝 YYYYMMDD HH:mm`。
- 同一行内继续输入、暂停、确认中文候选、短暂失焦及后台自动保存均不结束输入；进入阅读视图会结算当前笔记的新条目。
- 在任务下缩进创建普通列表条目，行末只加 `YYYYMMDD HH:mm`。前缀“进展：”“卡点：”“等待：”均可自由输入。
- 勾选任务追加 `✅ YYYYMMDD HH:mm`；取消勾选删除完成时间；再次完成记录新的完成时间。
- 父子任务独立勾选。所有时间都直接存储在 Markdown 中，关闭插件也能阅读。
- 修改已有文字、移动或缩进条目不刷新时间。打开旧笔记不会批量补时间。
- 粘贴或拖入的记录保留原样，不补创建时间；之后仅修改其文字也不补。
- 无创建时间的旧任务被勾选时，只记录本次完成时间。

时间使用设备本地时区和 24 小时制，记录实际补写时刻。源码模式保留原文，实时预览及阅读视图弱化时间显示。

0.1.3 起新写入使用 `📝`、`✅`，不带方括号。已有的 `💪`、`[🆕]` 创建时间和 `[✅]` 完成时间仍可识别和维护，不批量改写已有笔记。

普通记录需要在 Markdown 中缩进为任务的子列表；仅放在任务下一行、与任务同级的普通列表不会加时间。例如：

```md
- [ ] 父任务
  - 进展：已提交申请
```

输入记录后按 Enter 或移出当前行，第二行才会追加时间。可先在空行输入缩进的 `- `，再输入正文；前缀可自由选择。

## 撤销与阅读视图

编辑器内的勾选状态和时间属于同一次编辑事务，可以一起撤销或重做。中文输入法组合期间不插入时间。

阅读视图写入前核对源任务位置。有同文件、内容一致的编辑器时修改进入该编辑器历史；纯阅读情况下原子更新文件，不额外保证 Ctrl+Z。若已接管的源任务无法准确定位，插件不修改文件，并提示操作未执行。其他插件生成的任务列表和嵌入笔记不接管，请打开原笔记操作。

## 开发

需要 Node.js 24 和 npm。

```sh
npm ci
npm run dev       # 持续构建
npm run check     # TypeScript 检查
npm test          # 自动测试
npm run package   # 生产构建及安装包
```

依赖通过 `package-lock.json` 固定。构建产物和测试库不进入 Git。详细规则见 [需求说明](docs/requirements.md)，示例见 [工作记录](examples/工作记录.md)，实际验收见 [验证记录](docs/verification.md)。

## 复现宿主验收

构建后运行 `node scripts/prepare-qa.mjs`，在 `.qa-vault` 生成隔离测试库与 QA 插件。首次打开该库时，由操作者手动确认信任并启用插件。QA 插件在实际 Obsidian 的编辑器中执行事务检查，将结果写入库中的 `host-results.json`，生产安装包不包含 QA 插件。

宿主检查后继续在“手动验收”笔记中测试实际输入、点击复选框、视图切换、明暗主题和禁用插件。自动事务检查不能替代这些交互验收。
