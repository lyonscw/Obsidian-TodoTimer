真实事件日志已捕获提前结算：同一任务原文和光标 head 保持不变，`dom.blur` 后立即写入创建时间，见 [timing-fix-results.json](timing-fix-results.json)。现移除失焦结算，同文件后台事件不再全局 flush；编辑器重建只缓存和恢复本会话草稿，只有实际离行、切换笔记或进入阅读视图才结算。已通过短暂失焦、中文组合、同文件重建、快速视图切换、撤销与晚保存等自动回归。

新时间标记改为 `💪` 与 `✅`，旧括号格式继续识别。已验证旧创建时间不重复追加，旧完成时间可以取消，后续完成使用新格式。

本轮宿主探针的自动保存及同文件事件检查通过；之后人工合成焦点操作引发宿主编辑缓冲变化，探针未完成，不作为完整宿主验收。该合成流程已从 QA 脚本撤下。最终包未再次执行原生窗口或视觉验收。

## 此前验收中修复的问题

0.1.1：新子任务转为普通记录时，原实现按条目类型匹配身份，导致删除复选框后丢失新建候选。现按同一存活列表标记保留身份，并仅跟踪本次实际新建的普通列表；进入任务下后才可结算。旧行、粘贴、移动、外部载入不因此被当作新建。README 补充了缩进示例，说明任务下一行的同级普通列表不在记时范围内。

真实宿主检查发现：同一编辑窗口切换笔记时，旧编辑器不一定先失去焦点，导致尚未结算的新任务漏记创建时间。现保存旧文档快照并在对应文件保存后结算；写入前核对完整源文，保留 CRLF，已有源码分栏时通过其编辑事务修改。并发正文不匹配时不覆盖。

回归检查另覆盖两项宿主生命周期边界：文件身份早于正文更新时以新正文建立基线，避免旧任务误加完成时间；扩展移除后销毁流程使用最后有效状态，避免读取已移除的字段。相同内容笔记切换后的首次实际键盘或指针勾选仍正常记录。

运行 `npm run benchmark`，以普通任务与子记录组成 200、1000、5000 行文档，连续执行五次单字符输入。本轮一次测量的平均事务耗时约为 6、12、49 毫秒。

该探针不包含真实应用的 DOM 渲染、磁盘保存或输入法开销，不等同于宿主响应时间承诺。实现已消除逐条查找导致的平方级扫描；纯选择和结算操作复用解析结果及索引。
